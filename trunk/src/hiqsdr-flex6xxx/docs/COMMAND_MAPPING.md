# Карта команд Flex API

## Текущее состояние

Нет, сервер пока не реализует все команды AetherSDR. Он обеспечивает
подключение, обнаружение, один slice, один panafall, спектр, водопад,
аудиопоток и S-meter. Многие остальные команды сейчас получают успешный
ответ `R...|0|`, хотя фактически ничего не меняют. Такое поведение нельзя
сохранять: AetherSDR считает, что радиостанция выполнила команду.

Правило для шлюза: каждая принятая команда должна иметь один из результатов:

1. Изменить состояние шлюза и отправить соответствующий статус Flex API.
2. Выполнить операцию на HiQSDR, затем обновить состояние и статус.
3. Вернуть явную ошибку неподдерживаемой команды. Нельзя отвечать успехом
   для проигнорированной команды.

## Команды, работающие сейчас

| Группа | Команды | Действие |
| --- | --- | --- |
| Подключение | `client gui`, `client udpport`, `info` | Создание сессии и назначение UDP-порта клиента. |
| Подписки | `sub radio`, `sub slice`, `sub pan`, `sub meter` | Отправка начальных статусов. |
| Приёмник | `slice tune 0 <MHz>`, `slice list` | Меняется частота тестового slice. |
| Потоки | `stream create type=remote_audio_rx`, `stream create ...` | Создаются идентификаторы тестовых потоков. |
| Микрофон | `mic list` | Возвращается тестовый источник `MIC`. |

## Разделение ответственности

`FlexControlServer` не должен содержать код оборудования. Его задача -
принять Flex-команду, проверить аргументы, вызвать операцию backend и
сформировать Flex-статус или ошибку.

| Слой | Назначение |
| --- | --- |
| `FlexControlServer` | TCP/UDP Flex API, разбор команд, сессии, статусы. |
| `RadioBackend` | Единый набор операций приёмника, не зависящий от протокола Flex. |
| `TestRadioBackend` | Текущий генератор IQ для разработки без устройства. |
| `HiqSdrBackend` | Адаптер к функциям `hiqsdr_*` реального устройства. |
| DSP/VITA | Фильтрация IQ, расчёт уровней, спектр, водопад, аудио и VITA-пакеты. |

Переход с эмулятора на устройство должен сводиться к замене
`TestRadioBackend` на `HiqSdrBackend`; код протокола Flex и DSP при этом
остаются прежними.

## Соответствие Flex API и HiQSDR

| Группа Flex-команд | Примеры | Обработка в шлюзе | Операция HiQSDR |
| --- | --- | --- | --- |
| Настройка slice | `slice tune`, `slice set ... freq` | Частота slice, статус `slice` | `hiqsdr_set_frequency` |
| Полоса приёмника | `filt`, `slice set ... filter_*` | Параметры DSP-фильтра и статус slice | `hiqsdr_set_bandwidth` для полосы дискретизации; узкий фильтр выполняет DSP |
| Вход и усиление | `slice set ... rxant`, `preamp`, `rfgain` | Проверить допустимые значения, сохранить состояние | `hiqsdr_set_antenna_input`, `hiqsdr_set_preamp`, `hiqsdr_set_attenuator` |
| Предселектор | Команды выбора диапазона/предселектора | Состояние диапазона и диагностика | `hiqsdr_set_preselector` |
| Панорама | `display pan create/set/remove`, `display panafall ...` | Локальное состояние отображения, параметры FFT и VITA | Нет отдельной операции HiQSDR |
| RX-аудио | `stream create type=remote_audio_rx`, `stream set ...` | Создать поток, демодулировать IQ, отправлять VITA | HiQSDR отдаёт входной IQ через callback |
| Измерители | `sub meter`, `meter list` | Вычислить уровни из IQ и фильтра slice | Нет отдельной операции HiQSDR |
| Передача | `radio set ...`, `interlock`, `tx ...`, `stream create type=remote_audio_tx` | Отдельная безопасная TX-машина состояний | `hiqsdr_set_ptt` только после проверки возможностей устройства |
| Системные | `radio ...`, `client ...`, `sub ...`, `keepalive` | Состояние шлюза, ответы и статусы | Нет |

## Команды Flex, которые не следует имитировать успехом

До реализации должны возвращать явную ошибку: несколько независимых
приёмников сверх возможностей HiQSDR, DAX, CWX, DVK, TNF, память/профили,
USB-кабели, внешний усилитель, трансвертер, GPSDO, SmartLink и управление
несколькими передатчиками.

Часть из них позднее можно реализовать как функции шлюза, а не HiQSDR:
например, профили, память, TNF и DAX. Наличие команды в Flex API не означает,
что для неё существует аппаратный эквивалент в HiQSDR.

## Порядок реализации

1. Заменить общий успешный ответ на диспетчер команд с журналом каждой
   команды и явным статусом для неподдерживаемых.
2. Вынести состояние приёмника и поддерживаемые операции в `RadioBackend`.
3. Перенести текущий генератор в `TestRadioBackend`, сохранив работу
   AetherSDR без оборудования.
4. Добавить `HiqSdrBackend`, который вызывает `hiqsdr_init`,
   `hiqsdr_connect`, `hiqsdr_set_frequency`, `hiqsdr_set_bandwidth`,
   `hiqsdr_set_attenuator`, `hiqsdr_set_antenna_input`,
   `hiqsdr_set_preamp`, `hiqsdr_start_asynch_input` и, после отдельной
   проверки безопасности, `hiqsdr_set_ptt`.
5. Добавлять группы Flex-команд по журналу реальной сессии AetherSDR и
   закреплять каждую группу тестом протокола.

## Ближайшая граница первой версии

Первая аппаратная версия должна полностью поддержать один приёмник:
подключение, настройку частоты, выбор входа, предусилитель/аттенюатор,
полосу, один panafall, спектр, водопад, RX-аудио и S-meter. Передачу не
включать до отдельного согласования логики interlock и PTT.
